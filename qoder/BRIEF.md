# Qoder 竞赛开发简报

本文件是给 Qoder 的需求输入，尚非开发记录或完成证明。主功能代码、测试、文档和网站须由已登录的 Qoder 会话实际生成、调试并留存会话证据。

## 项目：Evidence Desk

解决团队周报与科研记录散落、证据难找的问题。用户可导入一组带来源与日期的工作记录，按关键词和日期查找，选中记录后生成带精确来源的周报草稿。核心存储和检索使用 seekdb MySQL 协议；没有 seekdb 时主流程应明确报错，不用内存假数据冒充。不要依赖付费模型或外部 API。

## 交给 Qoder 的开发任务

在 `qoder/` 下实现一个可运行的本地 Web 应用及自动化验证：

1. 使用 Python 3.11+、Flask、PyMySQL。提供 SQL 初始化脚本，记录字段至少有 id、标题、正文、来源、日期、标签。
2. 提供导入样例数据、搜索、查看来源、选中多条生成周报草稿的完整流程。搜索必须由 seekdb SQL 处理，支持关键词与日期条件；输出显示来源和被选中的记录 id。
3. 用环境变量配置数据库连接，提供 `.env.example`，不要写入账号、密码、令牌或私有地址。所有 SQL 参数化，验证输入长度与日期。
4. 编写至少一组自动化测试和一组端到端手工样例，保留真实执行命令、版本、退出码与结果。记录至少一次实际 seekdb 查询及其对产品流程的作用。
5. 编写中文 README，从空数据库初始化到启动、导入、查询、生成周报的命令均可复现。记录 Qoder 对需求拆解、编码、调试的真实会话证据和 Qoder UID；不得伪造。
6. 由 Qoder Sites 创建并发布公开项目网站。网站含项目简介、痛点、核心功能、真实演示截图或录屏、代码仓库链接和体验入口（如可用）；无痕窗口确认无需登录即可打开。网站若仅是展示页，应清楚说明本地应用的运行方式。
